# MLAI community arcade

The homepage team section launches a local 15-character fighting game. Every member can be selected independently as the human or CPU fighter, including mirror matches. Press Start carries the currently viewed team member into the player slot. The original team profiles and profile links remain available.

Both selection panels have a compact roster and a search field that matches names, roles and special moves. Each chosen fighter has a separate identity preview, fighting style and special description. Selection photographs reuse the existing small team thumbnails; opening the menu does not download combat sheets or the game engine. The two panels stack on small screens, with normal keyboard navigation and touch targets at least 44 pixels wide.

`team.tsx` loads `ArcadeShell.tsx` only after Press Start. Match confirmation imports `runtime.client.ts` and Phaser. The `.client` suffix excludes the engine from Worker execution. The runtime loads just the selected character sheets, deduplicating mirror matches. A failed required asset keeps the error screen visible until retry or cancellation.

The game uses a 60 Hz TypeScript simulation, independent of React rendering. `roster.ts` holds stable fighter IDs, profile identity, selected-sheet paths and movement/reach tuning. `specials.ts` is the single source for each move's name, description, mechanics and frame data; selection, CPU combat and rendering consume it. `core/combat.ts` owns movement, frame data, collision, hit/block stun, meter, projectiles, rounds and delayed-observation CPU decisions. `core/input.ts` retains short button presses until a simulation tick consumes them. React receives HUD snapshots at a limited rate and owns accessible menus and touch controls.

Each round lasts 60 seconds. The first fighter to win two rounds wins the match. Equal-health timeouts and double KOs replay the round; three drawn rounds finish the match as a draw. Meter resets each round. Normal hits earn 10 meter, blocked normal attacks earn four, and taking an unblocked hit earns five. Specials cost 50, and their chip damage cannot cause a KO.

Keyboard controls are A/D or arrows for movement, W/Up/Space for jump, S/Down for crouch, J for punch, K for kick, L for special, Shift for guard and Escape for pause. Crouch plus punch is a low attack; aerial attacks are overheads. Movement, attack and guard also have independent touch pointers. Controls are scoped to the focused arena. Focus loss, hidden documents and leaving the viewport pause the match and clear held inputs. Resume is explicit.

`arcade-focus.ts` coordinates the fighter with the other homepage games. Tetris releases its active controls while the arcade is open; its hook-based interactive implementation is separate from its reduced-motion fallback. Exiting or changing matches aborts the old runtime and invalidates late downloads. One shared host sits outside the team's responsive desktop/mobile branches.

All 15 character sheets are original AI-generated artwork with 16 action keyframes each: two idle, two walk, punch windup/extension, kick windup/extension, crouch/low attack, high guard, jump, hurt, defeat, special and victory. Simulation timing drives their playback. Sprite cells are 256 by 256, with a feet origin at y=230. The rooftop stage and sound cues are generated by the game code. Use `scripts/prepare-team-arcade-assets.py` to repack Sam/Sonia and build homepage thumbnails/reduced-motion previews. Use `scripts/prepare-team-arcade-roster.py --manifest <local-manifest.json>` for the other 13 sheets; its manifest is a list of `{ "id": "ryan", "source": "/absolute/path/to/generated-sheet.png" }` records. Alpha components preserve complete extended kicks and defeated poses when artwork strays across a nominal source cell. Both packers use Python and Pillow. Generated source sheets and working prompts belong in local task files; served assets are versioned under `public/games/team-arcade/v1/` (Sam and Sonia) and `public/games/team-arcade/v2/` (the remaining team). Sheet requests use the roster path rather than deriving an asset version from the fighter ID.

Set `VITE_TEAM_ARCADE_ENABLED=false` at build time to remove the Start actions. Profile links remain available. Changing this Vite flag requires a rebuild.

Run checks from the project root:

```sh
bun install --frozen-lockfile
bun run test:arcade
bun run typecheck
bun run build
bun run test:arcade:browser
```

The dedicated browser suite runs the production Worker preview and covers Chromium desktop, a Chromium phone viewport with actual multi-touch protocol events, and WebKit. It checks lazy network requests, all roster choices, search, independent selection slots, mirrors, human and CPU damage, a real complete match, pause/resume, results/rematch, asset retry, cancelled loading and 20 start/exit cycles. The article suite excludes these JavaScript-dependent journeys; CI installs both browsers and runs each suite with its own configuration. Install the matching Playwright Chromium and WebKit browsers before first use. Browser captures remain in `.local/`. Emulated phone and WebKit tests do not replace testing on physical phones.

Local Worker homepage caching uses the `local` build revision. For repeated preview rebuilds, use a query such as `/?arcade-check=browser` to fetch a fresh SSR document. Deployment builds receive their source revision through the existing Workers CI configuration.
